# 怎么写扩展

扩展让你在不改主程序的前提下，给自己的机器人加功能。更新主程序不会动你的扩展。
**扩展是 Python 代码，装上就和主程序有同样的权限（包括能读到机器人的 AppSecret），只装你信得过的人写的。**

## ⚠ 先看这个：扩展有危险

扩展是**和机器人本体一样权限**的 Python 代码，没有沙盒。装之前请想清楚：

- 它能读到机器人密钥（AppSecret、`.env`）、整个数据库，能把它们发到别处。
- 它能删文件、改数据库、改所有玩家的属性，**写错一行就可能把全体玩家的数据改坏**。
- 死循环、同步的长时间等待、疯狂发消息，会让整个机器人卡死，或被平台限流甚至封号。
- 装之前的自动检查只能拦住一部分明显的问题，**拦不住恶意代码，也拦不住写错的逻辑**。

所以：

1. **只装自己写的、或信得过的人写的。** AI 写的也要过一遍它做了什么，别直接上线。
2. **装之前备份**：整个数据目录（`data/`，里面有数据库）复制一份。
3. 先在测试群试，确认没问题再开给玩家。
4. 改数据（`set_attr` 之类）要有范围限制，别写「给所有人 +100」这种一条指令改全员的东西。
5. 出问题：启动前设 `CHANGRI_SAFE_MODE=1` 只跑核心功能，再回设置平台关掉它。

## 一个扩展长什么样

一个文件夹，放进 `extensions/`（或打成 zip 在设置平台「功能与设置」页上传）：

```
extensions/
  hello_demo/
    manifest.json      ← 说明书
    __init__.py        ← 代码
```

完整例子在 `docs/示例扩展/hello_demo/`，照着改最快。

### manifest.json

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 小写字母、数字、下划线，字母开头，2–31 个字符。**必须和文件夹名一样**，不能和官方扩展重名 |
| `name` | 是 | 显示名 |
| `version` | 是 | 版本号，随便写，如 `1.0.0` |
| `author` `description` `homepage` `license` | 否 | 显示在扩展列表里 |
| `api` | 否 | 需要的 changri_api 版本，默认 1。比主程序的版本高就拒绝加载 |
| `settings` | 否 | 设置项列表，设置平台自动给它们生成表单，见下 |

### 给扩展加设置项

在 `manifest.json` 的 `settings` 里写几项，设置平台就会在你扩展那张卡片上自动出现「进入设置」，点开是一个和官方功能一模一样的设置窗口，不用自己写任何网页。

```json
"settings": [
  {"key": "greeting", "label": "招呼语", "type": "string", "default": "你好呀", "desc": "回复里的第一句话"},
  {"key": "loud",     "label": "大声一点", "type": "bool", "default": false, "desc": "打开后末尾加感叹号"},
  {"key": "times",    "label": "重复次数", "type": "int", "default": 1, "unit": "遍", "desc": "招呼语说几遍"},
  {"key": "mood",     "label": "语气", "type": "choice", "choices": ["温柔", "元气"], "default": "温柔"},
  {"key": "note",     "label": "备注", "type": "text", "default": "", "desc": "多行文字"}
]
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `key` | 是 | 英文名，只能用字母数字下划线，代码里靠它读 |
| `label` | 建议 | 窗口里显示的名字，写人话（「招呼语」，不是 greeting） |
| `type` | 否 | `string`（一行文字，默认）、`text`（多行）、`int`（数字）、`bool`（开关）、`choice`（下拉，再加 `"choices": [...]`） |
| `default` | 建议 | 没设置过时用的值 |
| `desc` | 建议 | 名字下面一行灰色小字，说明这项是干什么的、填什么格式 |
| `unit` | 否 | 只给 `int` 用，数字旁边显示单位（秒、次、字） |

窗口里的样子：开关一行一个、右边是开关；数字右对齐，带单位；一行文字和多行文字占满整行；底部有固定的「保存 / 取消」。手机上一样好点。

写设置项的小原则：
- 一项只管一件事；名字写「每天最多几次」，别写「limit」。
- 开关的 `desc` 写清楚「打开后会怎样」；数字的 `desc` 写清楚「0 代表什么」。
- 默认值要能直接用，玩家不碰设置也应该是个合理的状态。

在代码里用 `setting(EXT_ID, "greeting")` 读，已经按类型转好了（`int` 是整数，`bool` 是 True/False）。改了设置马上生效，不用重启。

### 代码

它就是一个普通的 NoneBot 插件。**只从 `changri_api` 取东西**：

```python
from changri_api import Bot, GroupMessageCreateEvent, on_command, sender_role, reply_long, setting

cmd = on_command("打招呼", priority=10, block=True)

@cmd.handle()
async def _(bot: Bot, event: GroupMessageCreateEvent):
    role = sender_role(bot, event)          # 说话的人绑的角色，没有就是 None
    await cmd.finish(f"{role['name']}，你好" if role else "你还没有角色")
```

## changri_api 能用的东西（API 版本 1）

| 名字 | 作用 |
|---|---|
| `on_command` `on_message` | NoneBot 的原样，注册指令 |
| `Bot` `GroupMessageCreateEvent` | 类型，handler 参数里用 |
| `scheduler` | 定时任务：`@scheduler.scheduled_job("interval", seconds=60)` |
| `sender_role(bot, event)` | 发言人的角色，没有返回 None；可用 `role["id"]`、`role["name"]` |
| `role_by_name(name)` `all_roles()` | 按名字找角色、列出所有角色 |
| `is_admin(bot, event)` | 发言人是不是机器人管理员 |
| `send_group(bot_id, group_openid, text)` | 发到某个群，够长自动发图 |
| `send_to_role(role_id, text)` | 发到某个角色的个人群，返回是否送达 |
| `announce_group()` | 公告群 `(bot_id, group_openid)`，没设置返回 None |
| `backstage_group()` / `water_group()` | 后台群 / 水群，同上 |
| `staff_notice_group()` | 给管理组发提醒：后台群优先，没设就公告群 |
| `reply_long(matcher, text)` | 回复触发指令的人，够长自动发图 |
| `get_attr` `set_attr` `list_attrs` | 角色属性（跑团骰子也读这个） |
| `season_name()` `game_day()` `day_key()` | 进行中的季度名、现在 D 几、「今天」的唯一标记（做每日次数限制用） |
| `register_pending(名字, fn)` | 往玩家的「我的待回」里加一段：`fn(role)` 返回字符串列表，没有就返回空列表 |
| `setting(ext_id, key)` | 读自己的设置项 |
| `read_config(key)` | 读主程序的某个配置（只读） |

不在这张表里的东西，不保证以后还在。需要别的？告诉作者加到 changri_api 里。

## 扩展怎么读数据

只能通过 `changri_api` 拿。下面是「想做什么 → 用什么」：

| 想拿什么 | 怎么拿 | 说明 |
|---|---|---|
| **玩家清单**（有哪些角色） | `all_roles()` | 每项可用 `r["id"]`、`r["name"]` |
| 发言人是谁 | `sender_role(bot, event)` | 没绑定角色时是 `None`，要先判断 |
| 按名字找人 | `role_by_name("名字")` | 没有返回 `None` |
| 某人的属性（HP、金币等） | `get_attr(role["id"], "HP")` / `list_attrs(role["id"])` | 属性不存在返回 `None` |
| 改某人的属性 | `set_attr(role["id"], "金币", 50)` | 返回 `(是否成功, 说明)`，**要检查，失败原因回给玩家** |
| 季度 / 第几天 | `season_name()` `game_day()` `day_key()` | 没有季度时 `game_day()` 为 `None` |
| 主程序的某个配置（只读） | `read_config("brand_name")` | 改不了 |
| 自己的设置项 | `setting(EXT_ID, "key")` | 见「给扩展加设置项」 |

**玩家清单示例：**

```python
from changri_api import on_command, all_roles, reply_long, get_attr

who = on_command("谁有钱", priority=10, block=True)

@who.handle()
async def _(bot, event):
    rows = []
    for r in all_roles():
        gold = get_attr(r["id"], "金币")
        if gold is not None:
            rows.append((gold, r["name"]))
    rows.sort(reverse=True)
    await reply_long(who, "\n".join(f"{n}：{g}" for g, n in rows[:10]) or "还没有人有金币")
```

**暂时没有的：** 物品栏、商城、地点、关系线、公知二表、心动信目前**没有开放接口**。想要就告诉作者加进 `changri_api`，**不要自己去读数据库里的表**（表结构以后会变，直接碰还可能写坏数据，装的时候也会被标黄提醒）。

**扩展自己的数据**：数据少就用属性（`set_attr`，名字加前缀，如 `签到_连续天数`）；数据多就在扩展文件夹里自己写 JSON 文件，不要碰主程序的数据库。

## 规范（装之前会自动检查）

上传时主程序会读一遍你的代码，**有下面这些问题会直接拒绝安装**：

- Python 语法错误，或文件不是 UTF-8 编码
- 调用了 `os._exit` / `sys.exit` / `exit()` / `quit()` / `os.kill`（会让整个机器人退出）
- 指令名和主程序重名（比如你也写一个「约会」「时间线」），会劫持主程序的指令，换个名字

下面这些**会安装，但在扩展列表里标黄提醒**：

- `time.sleep`、`requests`：同步的等待会卡住整个机器人，请用 `await asyncio.sleep(...)` 和 `httpx` 的异步写法
- `subprocess` / `os.system` / `eval` / `exec` / `shutil.rmtree`：运行命令、动态执行代码、删文件夹
- `on_message` 设了 `block=True`、或 `priority` 小于 5：会抢在主程序前面拦住所有人的消息，一般写 `priority=10`、`block=False`
- 直接 `import core...`：只从 `changri_api` 取东西，core 里的名字以后可能改
- 读写 `.env` 或 `changri.db`：机器人密钥和数据库不要直接碰

**出错会怎样：**

- 加载时报错：只有这个扩展加载失败，原因写在列表那一项里，别的功能照常。
- 运行时某条指令里抛异常：只影响那一次指令，机器人继续工作。
- 打开扩展后机器人启动不起来（崩溃、被杀、死循环）：下次启动会**自动把上次新加载的用户扩展全部停用**，设置平台照常能进，你可以改好再打开。
- 实在进不去：启动前设环境变量 `CHANGRI_SAFE_MODE=1`，只跑核心和官方功能。
- 防不住的：死循环、同步的长时间等待会卡住机器人；扩展有完整权限，恶意代码也防不住。**只装信得过的人写的。**

## 好习惯

- 数据要存就用 `set_attr` 之类的 API，或自己在扩展文件夹里建文件；不要改主程序的表。
- 每条指令都回话（成功、失败、用法提示），别让玩家发了没反应。
- 回复很长就用 `reply_long`，会自动发图。
- 一个扩展只做一件事，名字写在 manifest 的 `name` 里让人一眼看懂。

## 注意

- 指令前缀：主程序认 `/`、`.`、`。` 和不带前缀。太短的纯英文指令容易被聊天误触，建议要求用户带前缀，或者用中文指令名。
- 官方机器人每次回复最多 5 条，主动发群有频率限制，不要刷屏。
- 在设置平台「功能与设置」页打开你的扩展的开关，再点「重启并生效」才会加载。上传的扩展默认是关的。
- 扩展出错加载不了，会在扩展列表那一项里写出原因，不影响主程序。

## 让 AI 帮你写

把这份文档和 `docs/示例扩展/hello_demo/` 里的两个文件，连同你想要的功能，一起发给 AI，让它「按这个格式写一个扩展」就可以。写完把文件夹打成 zip，在「功能与设置」页上传。
