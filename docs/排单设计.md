# 排单模块设计（个性化模块，独立于恋综）

状态：**设计稿，等作者确认后才实现。** 内容来自 2026-11-18 跟作者的逐条讨论。

## 1. 要做什么

给一个接稿的人（下面叫 **owner**）管理排单：她有好几种业务（溶图、板鞋、套框……），每种业务一个工作群；客户买了某种业务的若干「张」额度，在自己的客户群里下单、补图；owner 在工作群里把图交付回去，再到网页上扣张数。另有一种没有客户档案的**散单**，凭兑换码下单。

机器人负责：下单格式、登记单号、把订单和图转到对应的群、算单口和额度、到期提醒、工期催单、暂停顺延。

| 名词 | 意思 |
|---|---|
| 业务 | 一种服务，比如 A、B、C。有自己的工作群、工期天数、默认单口、下单格式 |
| 客户 | 固定一个人，有自己的客户群 |
| 额度 | 客户买的一笔张数：业务 + 张数 + 到期日期。同一业务可以有好几笔 |
| 单口 | 同一客户同一业务**同时最多几单没完成**（按单数算，不按张数） |
| 订单 | 一次下单，单号 `业务字母-流水号`（A-0001），每个业务各自从 1 编 |
| 散单 | 没有客户档案的人，在共用的散单群里凭兑换码下单 |
| 兑换码 | owner 在后台生成，一个码下一单，生成时定业务和有效期 |

## 2. 开关和入口

- 个性化模块：`features/paidan/__init__.py` 的 `FEATURE` 写 `personal: True`、`default_on: False`，照故事历的做法。新装、更新后都关着，「全部恢复默认设置」也关回去。
- 打开后，后台左侧「额外」下面新增一个小分组「附属功能」，里面是「排单」。关着时不显示（要改 `admin/templates/base.html` 的「额外」那段）。
- 关着时：群指令都不响应，定时提醒和暂停都不跑。**数据全部保留**，再打开一切照旧。
- 自己的表（前缀 `pd_`），不读写恋综的任何数据。跟别的数据一样按机器人分库。

## 3. 绑定

都用「网页生成绑定码 → 在群里发 `绑定 绑定码`」，绑定码一次性有效。

| 绑什么 | 谁发 | 记下什么 |
|---|---|---|
| 业务的工作群 | owner | 这个群 = 业务 A 的工作群 |
| 客户群 + 客户本人 | **客户本人** | 这个群 = 客户群；发消息的人 = 客户（以后 @ 他） |
| 散单群 | owner | 这个群 = 散单群（大家共用） |
| owner 本人 | owner，在任意机器人在的群里发 `绑定 owner码` | owner 的身份，用来 @ owner、认 `发送` 指令 |

- 客户绑错了人（比如 owner 自己发了码）：网页上解绑重来，或者手动改。
- **owner 只有一个**（作者确认）：一开始用 owner 码绑定一次，就跟那个 QQ 号对应。换号了在网页上重新生成 owner 码再绑，覆盖旧的。
- 实现：要同时记官方机器人给的群 / 成员 openid，和 QQ 号连接那边的真实群号 / QQ 号。现有的认群码（`bind_codes`，迁移 0019）就是做这种对应的，尽量复用。

## 4. 下单

1. 客户在客户群（或散单的人在散单群）发 `下单`。
2. 有多个业务可选时，机器人先给业务按钮 `A` `B` `C`；只有一个就跳过。
3. 机器人给出说明和 **「获取格式」** 按钮（`buttons.Btn(enter=False)`，只填进输入框）。格式是 owner 在网页上给每个业务写好的，第一行是标记，比如 `【A下单】`。散单群里的格式多一行 `兑换码：`。
4. 客户填好发出。**只能发文字**。
5. 机器人检查：
   - 今天不是暂停日（暂停时回复「今天暂停接单」，不登记）
   - 普通客户：这个业务的单口没满，并且**至少还有 1 张有效额度**（不按在排单数预留）
   - 散单：兑换码存在、没用过、没过期、业务对得上（散单不限在排单数）
   - 格式里的必填项都填了
6. 通过：生成单号；散单把兑换码标成已用（记下是谁用的、哪个单号）。
   - 客户群 / 散单群回复：「下单成功，单号 A-0012。补图请回复图片并写上单号，传完发『已上传所有图 A-0012』」
   - 工作群推送：单号、客户名（散单标「散单」）、格式内容，@ owner
   - **私聊 owner**（作者2026-11-18 加的）：机器人私聊 owner 一条，例如：
     ```
     【123456789/小明 已排单-A-0012-DDL 11/25】
     11/18 14:32 下单
     兑换码：无（散单写「有：H3KD9W2Q」）
     名称：猫猫
     尺寸：A4
     ```
     - 用 `send_to_c2c`，对象是绑定 owner 时记下的 openid（暗骰私聊也是这么发的）。官方机器人只能私聊白名单里的人，owner 自己负责把自己加进白名单。
     - 私聊发不出去（没加白名单等）不影响下单，工作群照常推送；后台排单页提示「私聊 owner 失败，检查白名单」。
     - 第一行是作者定的播报格式：`【QQ号/客户名 已排单-单号-DDL 日期】`，散单的客户名写「散单·名字」。
     - **QQ 号从下单格式里来**（官方机器人拿不到真实 QQ 号）：每个业务的下单格式都要有 `QQ号：` 这一栏，**没有「QQ号：数字」（5–12 位）就交不了单**，机器人回复「要写『QQ号：』加你的 QQ 号」。
     - owner 写的格式里漏了这一栏：「获取格式」时自动补在最后；后台编辑业务时也显示提醒「记得加上 QQ号 这一栏」。
     - 客户档案里也可以填 QQ 号（选填），只在 owner 网页补录、格式里没写时用。
     - **客户群的真实群号**（作者加的）：建客户时 owner 在网页上填（选填，官方机器人看不到真实群号），私聊播报里多一行「客户群：群号」，方便 owner 直接找到这个群。散单没有。
7. **下单时不扣额度**，扣额度在完成时（见 §6）。
8. 散单要记下**下单人**（QQ / openid），交付时 @ 他。
9. 客户不能自己改单、取消单，只能找 owner 在网页上处理。

## 5. 补图和锁定

- 客户在客户群 / 散单群里发图，**回复这张图**写单号 `A-0012`，机器人把图转到这个业务的工作群，附「A-0012 · 小明 · 补图」。
- **谁都可以补**，只要单号对（散单群也一样）。单号要属于这个群：客户群只能补自己的单，散单群只能补散单。
- 后台**不存图**，只记这单补过几张。
- `已上传所有图 A-0012`：**谁都可以发**，发了这单锁定，之后再补图回复「该单已锁定，无法继续上传」。工作群通知「A-0012 图已传齐，共 5 张」。
- 要再补：**只能 owner 在网页订单页点「打开传图」**（群里没有这个指令）；补完客户再发一次 `已上传所有图` 锁上。
- 锁定是给客户自己用的：出图前锁没锁都不影响。
- 订单完成后不能再补图，回复「该单已出图，无法补图」。

### 发送图包（作者加的）
- 图太多、要发一个大的合并转发时，客户在客户群（或散单群）里发 `发送图包`，**不用写单号**。
- 机器人私聊 owner：
  ```
  【图包】小明 要发送图包
  群号：987654321
  11/18 14:32，请到群里拿一下图包
  ```
  散单群写「散单群·发的人」，群号用后台填的散单群真实群号。
- 群里回复「已通知 owner 来拿图包，请把图包（合并转发）发在群里～」。
- 同一个群 10 分钟内只通知一次，再发回复「已经通知过 owner 了，请稍等～」。
- 官方机器人收不到合并转发里的图，所以不转发，只叫 owner 自己去群里拿。

## 6. 交付和完成

1. owner 在**工作群**发图，回复这张图写 `发送 A-0012`。只认 owner。
2. 机器人把图发到这单的群：普通客户 → 客户群 @ 客户；散单 → 散单群 @ **下单的那个人**。工作群回复「A-0012 已发送给 小明」。
3. `发送` **只负责发图，不改订单状态**，可以发很多次。第一次发送后订单标记「已发图，待扣张数」。
4. 网页后台出现提醒「A-0012 小明 已发图，请填写扣除张数」（总览和订单页都显示待处理数）。
5. owner 在网页上填：
   - **扣几张**：默认 1，按这单难度自己填（散单也要填，只记录，不扣额度）
   - **扣哪笔额度**：默认最早到期、还有余量的那笔，可以改选
   - 确认框先显示「将从 ① 扣 1 张、② 扣 2 张」
6. 确认后订单 **「已完成」**，这时才：扣额度、空出单口、不能再补图、不能再 `发送`。
7. 扣错了可以在网页上改（改张数或改到别的额度），按记录原样退回各笔。

### 扣额度的规则
- **跨笔扣**：选中的那笔不够，剩下的自动从下一笔最早到期的同业务额度扣，每笔扣了几张都记下。
- **全部额度加起来都不够**：提示「额度不足，本单要扣 3 张，只剩 1 张，将扣至 0，差 2 张」，确认后扣到 0、照样完成；后续 owner 自己跟客户沟通。这单记一条「差 2 张」的备注，客户页显示「有 1 单额度不足」，只做提醒，不影响以后录的额度。

## 7. 客户和额度

- 新建客户（网页）：名字；QQ 号（选填）；客户群的真实群号（选填）；每个业务的单口（默认取业务的默认单口，可改）；一笔笔录额度（业务、张数、**到期日期**用日期选择器）。
- 业务的默认单口改了，**已有客户不跟着变**；页面给一个「同步到没改过的客户」按钮，手动点才生效。
- 单口：同一客户同一业务，不管几笔额度，没完成的单加起来不超过单口数。
- 到期日当天还能用，第二天 0 点起作废（作者确认）。兑换码的有效期也按这个算。
- **过期**：剩余张数作废，记录保留，只能看，不能扣、不能延期、不能复活。owner 想补偿就新录一笔。
- **延期**：过期之前 owner 在网页上改到期日期，每次留一条记录（从哪天到哪天、什么时候改的）。延期后到期提醒按新日期重新算。

## 8. 散单和兑换码

- owner 在网页上批量生成：选业务、数量、**有效期**。一键复制整批，拿去外面的抢单渠道发。
- 每个码只能用一次，对应一单。
- 码的状态：未使用 / 已使用（谁、哪个单号）/ 已过期 / 已作废。
- owner 在网页上取消散单的订单：**兑换码直接作废**，不退回。
- **兑换码有效期也随暂停顺延**：每暂停一天，没用过、没过期的码有效期 +1 天（作者2026-11-18 改的，原来定的是不顺延）。
- 散单的单号跟普通客户共用业务编号（A-0013），工作群里的推送、补图、催单都标「散单」区分（作者确认）。
- 散单的下单、补图、锁定、交付流程跟普通客户一样，不同的只有：凭码下单、不扣额度、不限在排单数、交付 @ 下单人。

## 9. 每天中午 12 点的提醒

时间做成网页设置，默认 12:00。暂停那天不发。

| 提醒 | 发到哪 | 什么时候 |
|---|---|---|
| 额度到期 | 客户群，@ 客户 | 到期前 5、3、1 天；只提醒还有剩余的那笔 |
| 工期催单 | 订单所属业务的工作群，@ owner | DDL 前 5、3、1 天、当天；超期后每天继续，标「已超期 X 天」 |
| 待扣张数 | 工作群，@ owner | 每天，直到网页上填完 |

- DDL = 下单时间 + 业务的工期天数。业务工期比 5 天短时，早于下单的提醒自动跳过。
- **已经发过图的单不再催 DDL**，改进「待扣张数」提醒。
- 同一个工作群的多单合成一条，不刷屏，例如：
  ```
  【工期提醒】
  今日到期：A-0012 小明、A-0015 小红
  3 天后到期：A-0018 小刚
  已超期：A-0009 小李（超期 2 天）
  待扣张数：A-0007 小王
  ```
- 额度到期提醒例：「@小明 你的 A 业务额度还剩 2 张，将于 11/28 到期，过期作废，请尽快使用～」

## 10. 暂停

- 按天算：一次暂停一天，到当天 23:59 结束；第二天还想停就再点一次。
- **当天暂停**：网页上点「今天暂停」，点的那一刻生效，并立刻给**所有绑定过的客户群和散单群**发通知。
- **提前设置**：网页日历勾选未来某几天。设置时先发一条预告；到那天 **00:00** 生效并再发一条当天通知（时间做成设置，默认 00:00）；生效前可以取消某一天，取消时发「X 月 X 日恢复正常接单」。
- 每生效一天：
  - 所有**有效额度**的到期日 +1 天
  - 所有**没用过、没过期的兑换码**有效期 +1 天
  - 所有**在排订单**的 DDL +1 天
  - 当天不发到期提醒和工期催单
  - 群里 `下单` 回复「今天暂停接单，明天恢复～」；owner 在网页上手动补录订单不受限制
- 顺延在**生效那天**做，不在设置时一次加完，这样中途取消不用往回改。
- 通知按客户情况分两种：有在排单的说「今天无法下单，你在排的单和额度到期日都顺延 1 天」；没有的说「今天无法下单，明天恢复」。有有效额度的加一句「额度到期日已顺延 1 天」。

## 11. 网页页面（附属功能 → 排单）

- **总览**：在排单数（按业务）、待扣张数、今天 / 近几天到期的单、快过期的额度、今天是否暂停。
- **业务**：增删改业务（名称、字母、工期天数、默认单口、下单格式）；工作群绑定码和绑定状态。
- **客户**：列表和详情——绑定状态、QQ、各业务单口、额度（余量、到期、延期记录、过期）、订单、「额度不足」提醒。
- **订单**：按业务 / 状态筛选；单条可以：完成并扣张数、改扣法、打开传图、取消、手动补录。
- **散单**：散单群绑定、散单群真实群号（选填，图包通知用）；生成和导出兑换码；码的状态列表。
- **暂停**：今天暂停按钮；日历提前设置；暂停记录。
- **设置**：提醒时间（默认 12:00）、提前暂停通知时间（默认 00:00）、owner 绑定码和当前绑定的 owner。

开关类设置都用开关控件，不让人填 1 / 0。

|---|---|---|---|

| `下单` | 客户群、散单群 | 客户、散单 | 选业务、给「获取格式」按钮 |
| `【A下单】…` | 客户群、散单群 | 客户、散单 | 提交订单 |
| 回复图片 `A-0012` | 客户群、散单群 | 任何人 | 补图 |
| `已上传所有图 A-0012` | 客户群、散单群 | 任何人 | 锁定上传 |
| `补充 A-0012 内容`（也认 `补充需求`） | 客户群、散单群 | 任何人 | 下单后补充需求：接在下单内容后面（标「【补充 11/18 14:32】」），转到工作群 @ owner。锁定了图也能补充；完成、取消的不行；最多 500 字 |
| `我的额度` | 客户群 | 客户 | 看各业务还剩几张、每笔哪天到期、单口占用、在排的单号和 DDL |
| `发送图包` | 客户群、散单群 | 任何人 | 私聊 owner 带上群号，叫 owner 去群里拿合并转发 |

## 12½. 第二轮补的（作者2026-11-18 选的）

- **客户已完结**（作者最开始要的「用完的单口标记已完结」）：客户页「标记已完结」/「恢复」。完结后不能下单（回复「你的单口已经完结了」）、不发额度到期提醒和暂停通知、总览和客户列表里收起来；数据保留。有在排的单时不能完结。
- **完成后通知客户**：网页上第一次扣完张数，在客户群 @ 客户「A-0012 已完成，扣 2 张，溶图还剩 3 张。」；额度不够加一句「还差 X 张，owner 会跟你联系」。散单在散单群 @ 下单人「A-0012 已完成～」。改扣法不再通知。
- **取消订单通知客户**：「A-0012 已取消。（散单：兑换码已作废。）有问题请联系 owner。」
- **工作群没绑定时**，工期催单改成私聊 owner（`work_target`）；owner 也没绑就不发。
- **我的额度**：客户在客户群发 `我的额度`，见 §12 的指令表。
- **owner 改下单内容**：网页订单页「编辑内容」，只能改在排的单。

没做（作者没选）：录额度 / 延期通知客户、owner 在群里查排单、兑换码手动作废、业务停用。

## 12¾. 群指令和定时任务（plugins/paidan.py）

- 补图、发送都认两种发法：**图片和单号写在同一条**，或者**回复那张图写单号**（图从回复消息的 `msg_elements[].attachments` 里拿，要先打 `qq_compat` 补丁，机器人启动时会打）。图下载下来再发到对方群，不落盘。
- `绑定` 只认 6 位码，不认得的码不回话，留给别的功能。
- 下单格式在客户群 / 散单群以外发不理；散单群没写兑换码直接提示。
- 新单：客户群回复单号和补图方法；工作群推送（@ owner，工作群没绑定改私聊 owner）；私聊 owner 播报。私聊失败记在 `pd_dm_fail`，后台「设置」页显示红条。
- 定时任务每分钟一次：到了的暂停先顺延；暂停当天到了通知时间（默认 00:00）发一次暂停通知（网页上点「今天暂停」时已经发过，不重发）；到了提醒时间（默认 12:00）发一次额度到期提醒和工期催单，一天一次，重启后当天没发过会补发。
- 测试：`tests/test_paidan_e2e.py` 走真正的 NoneBot 事件分发（假机器人记下发了什么，图片下载用假的）。**没在真 QQ 上试过**：按钮、私聊白名单、回复图片时 QQ 实际推过来的格式都要上线后确认。

## 13. 实现要点和要先查清的平台限制

- **听不 @ 的消息**：补图、交付都是「回复图片 + 文字」，不会 @ 机器人。**作者的官方机器人开了自动听取（全量接收群消息）**（2026-11-18 确认），所以直接走官方机器人收，不依赖 QQ 号连接。要先在真机上确认两件事：① 收到的消息里能不能拿到「回复的是哪条消息」（被回复的那条里的图片）；② 拿不到的话，退路是图片和单号写在同一条消息里发（`发送 A-0012` + 图、`A-0012` + 图）。
- 没开自动听取的机器人（别的用户装了这个模块）：补图和交付会收不到，后台排单页要提示「需要开启自动听取」。
- **图片转发**：图从客户群转到工作群、从工作群转到客户群，只是中转、不落盘。官方机器人发图要先上传，参考 `qqsend.download_images` 和发长图的做法。
- **主动消息**：12 点提醒、暂停通知、交付都是主动发群消息。`qqsend.send_to_group` / `send_at` 现在就在用，但官方机器人主动消息的次数上限**要先查清**，提醒合并成一条也是为了省次数。
- **@ 人**：用 `qqsend.send_at`（markdown 的真 @，没权限时退回纯文字「@名字」）。
- **定时**：`nonebot_plugin_apscheduler`，每分钟检查一次是不是到了设置的时间（照现有 tick 的写法，`@per_bot`）。
- 代码位置：规则 `core/paidan.py`（不依赖 NoneBot / Flask，方便测试），群指令 `plugins/paidan.py`，后台 `features/paidan/admin.py` 和模板，迁移排在 main 当前最大的编号后面（现在是 0021，合并前再看一次）。
- 测试：额度跨笔扣 / 不足、单口、到期作废、延期、暂停顺延、兑换码、锁定这些规则都放在 core 里写单元测试。
