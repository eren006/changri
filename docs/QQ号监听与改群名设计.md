# QQ 号监听与改群名（设计稿）

状态：**设计稿，等 Erin 确认 QQ 号的接法后才实现。**

## 要什么（Erin 的原话范围）

用 Erin 自己的一个 QQ 号，**只做两件事**：
1. **监听**：收到群里的消息（官方机器人只能看到 @ 它的消息，这个号能看到所有）。
2. **改群名**。

**别的都不做**：不用这个号发消息、不做指令、不做完整的第二套机器人。机器人说话仍然只有官方机器人（卡拉）。

## 为什么可以做得很小

因为只收消息、只调一个接口，不需要把整个长日bot 改成同时支持两种账号（那要改 28 个文件、约 140 处）。只加一个独立的小模块：

```
QQ 客户端（NapCat / LLOneBot，用这个号登录）
        │  OneBot v11 反向 WebSocket（带口令）
        ▼
长日bot 里的 core/onebot_listener.py（新，独立于官方机器人那套）
        ├─ 收到群消息事件 → 交给 log 记录（跑团）
        └─ 调用 set_group_name(群号, 新名字) → 改群名
```

## 登录方式：像海豹那样，在后台扫码（Erin 的要求）

海豹的做法（官方手册 platform-qq 一页）：
- **内置客户端**：海豹自己启动并管理一个协议客户端进程（Lagrange.Milky 或 Yogurt），在 WebUI「账号设置」里选这个方式、填 QQ 号，**页面直接出二维码，用手机 QQ 扫码确认**，状态变「已连接」就完成。二维码过期要删掉连接重新加。容器里跑不了。
- **分离部署**：自己装 NapCat / LLBot 之类，在海豹里填连接地址；登录在那个客户端自己的界面里做。

长日bot 照第一种来：后台新增一页「QQ 号监听」，里面有 **启动 / 停止、二维码、连接状态**；长日bot 管理协议客户端的进程，Erin 只需要在这一页扫码。也保留「分离部署」：已经有 NapCat / LLBot 的，填地址和口令就行。

海豹手册里提到的注意事项，这里一样适用：
- 个人账号用第三方协议有被检测、警告甚至冻结的风险；
- 这个号**不能同时登录电脑版 QQ**，否则互相挤下线；协议可能要定期重新登录；
- 分离部署会多开端口，公网机器要有口令和防火墙。

**还没定的是用哪个协议客户端。** 海豹内置的 Lagrange.Milky / Yogurt 说的是「Milky」协议，不是 OneBot；NapCat / LLBot 说的是 OneBot 11。两者的事件格式不同，我们只需要「收群消息 + 改群名」这两件事，哪个都能接。实现前我会先做一个小调研（各客户端的二维码怎么取、在 Linux 贾维斯上怎么装、占多少内存），再回来让 Erin 选，**不会在没确认前动服务器**。

## 调研结果（2026-11-14）

**贾维斯的条件**：Ubuntu 24.04、x86_64、2 核、总内存 3.7G，当前可用约 2.1G（已经跑着长日bot、rp_archive、语擦日历、nginx 等），磁盘剩 56G。没有 Docker，没有 Xvfb。

| | Yogurt（Milky 协议） | NapCat（OneBot 11） | LLBot（OneBot 11） |
|---|---|---|---|
| 是什么 | Acidify 的 QQ 协议端，Kotlin 原生，一个可执行文件（有 linuxX64）；**海豹内置的就是它或 Lagrange.Milky** | 在 QQ NT 客户端里注入，要先装对应版本的 QQ；无显示器服务器要 Xvfb 或 cage，或用 Docker | 同样依赖 QQ NT，Docker 镜像约 145MB；登录界面文档提到 NoVNC |
| 在贾维斯上 | 预计最省事：单文件、不装 QQ、不要图形环境（**未实测**） | 要装 QQ + 虚拟显示，更重（内存数据没查到，凭经验比 Yogurt 大） | 同 NapCat，且文档不多 |
| 二维码 | 海豹内置时在 WebUI 里出二维码；Yogurt 自己怎么出（终端 / 图片 / 接口）**我没查到**：官方文档页是前端渲染，抓不到 | WebUI（默认 6099）里扫码，或看日志里的二维码 | 未确认 |
| 改群名 | Milky 有 `set_group_name`（参数 `group_id`、`new_group_name`），文档没写需要什么权限 | OneBot 有 `set_group_name` | 同 |
| 对接 | HTTP：`POST /api/:api`；事件：`GET /event` 走 SSE 或 WebSocket；口令用 `Authorization: Bearer`，SSE/WS 也可以用 `access_token` 参数 | OneBot 11：反向 WebSocket，口令 | 同 |
| 许可 | GPL-3.0（我们只调用它的接口，不嵌它的代码，进程分开跑） | — | — |
| 风险 | 较新；发布仓库只有 2 个提交，版本信息不明；资料少 | 资料多、用的人多；但要和 QQ 版本配套，QQ 更新会让它失效（海豹手册也提醒） | 资料少 |

**我的建议：Yogurt（Milky）。** 理由：和海豹的内置方式同一路线（Erin 要的「在后台扫码」就是这个）；单文件、不需要装 QQ 和图形环境，适合贾维斯这种内存有限、没有 Docker 的机器；`set_group_name` 和「收群消息」这两个我们要的接口都有；我们的接入也很小（一个 HTTP 调用 + 一个事件连接）。

**没验证的事（所以我没有往服务器装任何东西）**：
1. Yogurt 在贾维斯上的实际内存占用；
2. 二维码具体怎么取、登录后会话能保持多久；
3. 它的发布版本是否稳定（现在看起来是开发版）；
4. 这个号是群管理员 / 群主才能改群名（QQ 本身的规则），备用群里是不是都满足。

**建议的下一步（需要 Erin 同意才做）**：先做一个**小试验**，不写长日bot 的代码：在贾维斯上单独下载 Yogurt，用 Erin 的小号扫码登录，看 ① 内存占用 ② 二维码怎么出 ③ 能不能收到备用群的消息 ④ 能不能改群名。试验完了再决定是做进长日bot，还是改用 NapCat。试验可以随时关掉、删除，不影响现有服务。

## 群怎么对上号：这个号已经在备用群里

Erin 说明：这个 QQ 号已经在她的备用群里了，所以不用卡拉一个个被拉进群。这正好：
- 监听和改群名**只需要真群号**，不需要卡拉在群里；
- 后台「角色与群」里登记备用群时填的「群号」（`role_groups.real_gid`，原来只是个标签）就是对应关系：监听到哪个群号的消息，就能找到它属于哪个角色 / 房间；
- 卡拉没进、没认过群的备用群，也可以监听和改群名；只是**发消息**仍然只能靠卡拉，卡拉没进的群发不了。

## 监听用来做什么

- **跑团 log 自动记全**：这个号收到的群消息，在群开着 log 时写进 log，不需要 `/说`。发言人名字直接用 QQ 群名片 / 昵称，比 `/nn` 更省事。
- 官方机器人也会收到 @ 它的消息并记一份，两边会重复：按「同一句话、3 秒内」去重（和聊天记录导入用的是同一套去重）；机器人自己的昵称（卡拉）要在设置里填，监听时跳过。
- **只记登记过的群**：这个号看到的是真群号。跑团群要在后台登记「真群号」（或群里让卡拉发 `/群号 123456789` 绑定），没登记的群，这个号收到的消息一律丢掉，不落库。
- 不记录的规则（括号开头、`//` 开头、旁观者）照常生效。

## 改群名

- 只提供一个动作 `set_group_name(真群号, 名字)`。
- 入口：后台一个「改群名」按钮（在群池 / 房间页）；是否让房间开始 / 结束时**自动**改名，等 Erin 定（见下面问题 2）。
- 前提：这个号要是那个群的**管理员或群主**，否则 QQ 会拒绝，我们把错误原样告诉用户。

## 安全

- 反向 WebSocket 只接受带口令的连接，口令放 `.env`，不进仓库，不进日志。
- 默认只监听本机（127.0.0.1）；NapCat 和长日bot 在同一台机器上最简单。跨机器连接（比如连奥创上的 llbot）要开端口，必须有口令并且限制来源 IP。
- 这个号收到的所有群消息里，**只有已对上号的群、而且 log 正在记录时才写入数据库**，其余的在内存里就丢掉。
- 用个人 QQ 号跑 OneBot 违反 QQ 规则，有封号风险，建议用小号；不要碰索罗和 SealDice 的配置。
