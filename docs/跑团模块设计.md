# 跑团模块设计（独立于恋综的跑团系统）

状态：**设计稿，等 Erin 确认后才实现。**

## 1. 要做什么

Erin 的要求，我的理解：

1. 做一个独立的**跑团系统**（不是恋综），功能参考 SealDice 的 log。
2. 每个群可以在**跑团模式 / 恋综模式**之间切换，两种模式**各存各的数据**（比如属性）。
3. 基础的 COC / DND 规则已经有了（`core/dice.py`、`plugins/dice.py`），沿用，不重写。
4. 增加跑团的**录入属性**：用 `st`。
5. 增加 **log**：群里开始 / 停止记录，记录能在网页上**查看**。
6. log 可以**下载成 zip**，并且有**着色器**（给不同发言人上色）。

## 2. 先说一个硬限制：官方机器人看不到群里所有消息

SealDice 能记完整的群聊，是因为它挂在个人 QQ 上，能看到所有消息。QQ **官方机器人**只会收到 **@ 机器人** 的群消息（单聊是全收）。所以：

- 玩家的普通发言（不 @ 机器人）机器人**根本收不到**，没法自动记。
- 能自动记下来的只有：①@ 机器人发的消息；②机器人自己的回复（骰点结果）；③专门的记录指令。

我的解决办法有两层：

**A. 在线记**：开了 log 以后，记录以下内容：
- 所有 @ 机器人的消息（含骰点指令和结果，自动配对）；
- 新增 **`/说 台词`**（别名 `/s`、`/演`）：玩家发这条，机器人只记下不回复（或只回一个 ✓），用来记角色发言。不 @ 也不行，所以每次都要 @，这是官方机器人的限制，没法绕开；
- 括号里的内容默认**不记录**（见 §6 的「不记录规则」）。

**B. 导入补全（推荐搭配用）**：网页上提供「导入聊天记录」，把 QQ 导出的聊天记录 txt 粘贴/上传进来，按时间和发言人拆成 log 行，和机器人记的骰点按时间合并。这样跑团完整内容 = 手机 QQ 导出 + 机器人记的骰点，能在同一个页面里着色、查看、下载。

> 这点需要你确认：A + B 的组合你能接受吗？如果你的群开了「全量消息」权限（官方对部分机器人开放，需要在开放平台申请），这个限制会小很多，但目前卡拉没有，我也不能假设它有。

## 3. 模式切换

- 指令：`/模式 跑团` / `/模式 恋综` / `/模式`（看当前）。**每个群各记各的**，沿用 `dice_rule:<scope>` 同样的做法，存成 `play_mode:<机器人>|<群>`，只有群管理员能切（沿用现有管理员判定）。
- 默认：新群 = 恋综（和现在一致，已有群不受影响）。后台「功能与设置」里加一个默认模式。
- 跑团模式下：恋综的指令（短信、礼物、私约、心动信……）在这个群里**不响应**，避免串味；骰子、log、角色卡可用。恋综模式下：跑团的 `st`、`log` 不响应，骰子继续按现在的方式读恋综角色的属性。
- 单聊：不分模式，沿用现在行为。

## 4. 两种模式的存储（互不相通）

| | 恋综模式（现有，不动） | 跑团模式（新） |
|---|---|---|
| 属性挂在 | 恋综角色（`roles` / `role_attrs`） | **角色卡**（新表 `trpg_cards` / `trpg_card_attrs`） |
| 谁的 | 个人群绑定的角色 | 玩家（QQ openid），一个玩家可以有多张卡，每个群选一张「当前卡」 |
| 属性定义 | 后台「物品与地点」的属性定义（带上下限） | 不限定，随便写；COC/DND 的常用属性自动识别别名（力量=STR…） |

新表（建在每个机器人的工作区库，`CREATE TABLE IF NOT EXISTS`，老库不受影响）：

```
trpg_cards(id, owner_openid, name, rule 'coc'|'dnd', note, created_ts)
trpg_card_attrs(card_id, name, value)                 -- 整数属性，和 role_attrs 同形
trpg_active(scope, owner_openid, card_id)             -- 这个群里这个人当前用哪张卡
trpg_logs(id, scope, name, status 'on'|'off'|'ended', started_ts, ended_ts, token, palette_json)
trpg_log_lines(id, log_id, ts, speaker_key, speaker_name, kind 'say'|'dice'|'bot', text, ref)
trpg_attr_history(id, card_id, log_id, ts, name, old_value, new_value, source)   -- 属性每次变动一条；source：st / 检定成长 / 理智损失 / 后台手改；log_id 为空 = 不在任何战役里改的
trpg_log_members(log_id, owner_openid, card_id)                                  -- 这场战役谁、用哪张卡参加了
```

**「战役」就是一个 log**（一场跑团 = 一个 log，从 `/log new` 到 `/log end`）。角色卡的「历史战役」= 这张卡参加过的所有 log；「战役里的变动」= `trpg_attr_history` 里带这个 log_id 的记录。

## 5. 录入属性 `st`（跑团模式）

沿用 SealDice 的写法，大家已经习惯：

| 指令 | 作用 |
|---|---|
| `/st 力量60 敏捷50` 或 `/st 力量 60` | 录入 / 修改属性（支持 `+10`、`-5` 增减） |
| `/st` 或 `/st show` | 看当前卡的全部属性 |
| `/st 力量` | 只看某一项 |
| `/st del 力量` / `/st clr` | 删一项 / 清空 |
| `/pc new 名字` `/pc list` `/pc 切换 名字` `/pc del 名字` | 多张角色卡 |
| `/nn 名字` | 给自己在这个群里的显示名（log 里用它标发言人，也是官方机器人拿不到昵称的补救） |

`ra 侦查` 这类检定在跑团模式下读**当前卡**的属性；恋综模式仍读恋综角色。实现上只改 `plugins/dice.py` 的 `_lookup` / `_role_of` 一处：按群模式选数据源，`core/dice.py` 不动。

## 6. log 功能

指令（参考 SealDice 的 log，名字都有中文别名）：

| 指令 | 作用 |
|---|---|
| `/log new 名字` | 新建并开始记录（同一群同时只有一个在记） |
| `/log off` `/log on` | 暂停 / 继续 |
| `/log end` | 结束，返回网页链接和统计（条数、骰点数、发言人数） |
| `/log list` | 本群的 log 列表 |
| `/log get 名字` | 再给一次链接 |
| `/log del 名字` | 删除（需要管理员或开启者） |
| `/说 台词` | 记一条角色发言（见 §2） |

记录规则：
- 一行 = 一条消息：时间、发言人（用 `/nn` 的名字，没设就用「玩家1、玩家2…」自动编号）、类型、内容。
- 骰点结果以 `dice` 类型和发起指令的那条自动配成一组。
- 机器人别的回复（帮助、提示）不记，只记骰子相关输出。
- log 数量不限，后台能一键删；单个 log 超过 5000 行时提示。

**不记录规则**（Erin 提的，可在后台「跑团日志 → 记录规则」里改，每个机器人一份，单个 log 也能临时覆盖）：

| 规则 | 默认 |
|---|---|
| 括号包起来的内容不记（`（…）` `(…)` `【…】` `[…]`，全角半角都算，整条以括号开头才算，不是中间出现） | 开 |
| 以某些前缀开头的不记（默认 `//`、`##`，可自己加） | 开 |
| 指令本身（`/ra`、`/st`……）只记骰点结果，不记指令文字 | 关（关 = 指令和结果配对一起记） |
| 机器人的帮助、报错类回复不记 | 开 |
| 单个玩家被设为「不记」（旁观者、场外聊天的人） | 无 |

被规则跳过的消息**不会进数据库**，不是「记了再隐藏」，下载的 zip 里也没有。

## 7. 网页查看

两处入口：

1. **后台「跑团日志」页**（管理员）：列表 → 点进去看；改名、删除、导入、着色、导出都在这里。
2. **只读分享链接** `…/l/<token>`：`/log end` 给的就是这个，不需要登录，token 是长随机串，玩家能看不能改。放在小手机端口上（所以小手机要开）。这个链接是明文 http，和现在小手机同样的安全级别。

页面做法：手机宽度优先；每行左侧是发言人色块，右侧内容；骰点行用卡片样式把「掷了什么 → 结果 → 成功等级」排清楚；场外话默认折叠；可按发言人筛选、搜索关键词、跳到某一天。

### 7.1 后台「角色库」：按 QQ 号看所有角色和历史

Erin 提的：后台能看到每个 QQ 号登记的所有角色，点「详情」看数值和历史。

- **列表页**：每行一个 QQ 号（openid；有 `/nn` 名字就一起显示，机器人拿不到真实 QQ 号，只有官方给的 openid，同一个人在不同群里 openid 也可能不同，这点页面上注明），展开或点进去是这个人名下所有角色卡：卡名、规则（COC/DND）、所在群、最近一次使用时间、参加过几场战役。可搜索、可按 QQ / 卡名筛选。
- **每张卡右侧有「详情」按钮**，点开（抽屉或单独页）分三块：
  1. **当前数值**：全部属性，COC 自动算半值 / 五分之一值，DND 自动算调整值；管理员可以直接改（改了会记一条「后台手改」历史）。
  2. **历史战役**：这张卡参加过的所有 log，按时间倒序，每行显示战役名、起止时间、群、点进去跳到那场 log。
  3. **战役里的变动**：选一场战役，列出这场里属性的每次变化：时间、属性、旧值 → 新值、原因（`st`、理智损失、检定成长……），并给出这场「开始时 → 结束时」的对比。也能选「全部」按时间看这张卡的完整成长轨迹。
- 数据来自 `trpg_attr_history`：从上线那天起每次属性变化都记，上线前的变动查不到（所以建议第一步先上线）。
- 和 §7 的 log 页互相跳转：在 log 里点发言人 → 看这个人的卡；在卡里点战役 → 看那场 log。

## 8. 着色器

SealDice 的 log 着色器是给每个发言人配一种颜色再导出。我这边：

- 每个 log 有一份调色板 `palette_json`：发言人 → 颜色，默认从一组 10 色里按顺序分配（色盲友好，深浅色模式下都能读）。
- 网页上点发言人头像色块就能换色；也能整体换主题（浅色纸张 / 深色 / 纯文字打印用）。
- 可勾选：骰点高亮（大成功/大失败特别标）、场外话淡化、机器人行淡化。
- 着色结果会带进导出的 HTML。

## 9. 导出（含 zip）

下载的 zip 里放：

| 文件 | 内容 |
|---|---|
| `log.html` | 带着色的单文件网页，离线打开就能看，样式全内联 |
| `log.txt` | QQ 风格纯文本：`名字(2026-11-14 21:03:11)` 换行 `内容`，方便贴到别的平台 |
| `log.json` | 结构化数据（带发言人、类型、时间），将来可以重新导入 |
| `骰点汇总.txt` | 谁掷了多少次、大成功/大失败次数、技能成功率（跑团结束后很有用） |

也支持单独下载其中任何一个。

## 10. 代码放哪（符合现有架构）

- 规则与存储：`core/trpg.py`（卡、`st` 解析、模式、别名表）、`core/trpglog.py`（log 记录、导出、着色、导入），不依赖 QQ，可单独测试。
- QQ 指令：`plugins/trpg.py`，加入 CORE_MODULES，优先级 priority 10 block=True；**一个钩子**放在消息进来的最前面，只在「该群开着 log」时把消息写进 log（不拦截）。
- 后台：`admin/templates/trpg.html`（日志管理）、`trpg_cards.html`（角色库与详情）；设置项走现有 `field_view()` 开关写法。
- 小手机端口：`phone/app.py` 加 `/l/<token>`（只读）。
- 所有读写走 `get_conn()`，多机器人自然隔离；分享链接的 token 在各自机器人库里，不会串。
- 测试：模式切换隔离、`st` 解析（别名/增减）、log 配对、导出内容、token 只读。

## 11. 分四步，每步都能单独验证和部署

1. **模式 + 角色卡 + st**：`/模式`、`trpg_*` 表、`st`/`pc`/`nn`、骰子读当前卡、属性变动历史开始记；后台「角色库」列表和详情（数值 + 变动，战役部分等第 2 步有 log 才有内容）。
2. **log 记录**：`/log` 全套指令、`/说`、记录钩子、骰点配对、不记录规则；角色详情里的「历史战役」接上。
3. **网页**：后台日志页、只读分享链接、着色器。
4. **导出 + 导入**：zip / html / txt / json、骰点汇总、QQ 聊天记录 txt 导入。

每步：本地全量测试 + 浏览器实看（手机 375 宽、深浅色）；**你说「部署」才上线**。
