# 物品、地点、属性与商城迁移设计

> 部分规则改编自「长日将尽」CC BY-NC-SA 协议作品，来源及授权联系方式见旧系统 `长日RPG.js`。

状态：**Erin 已确认开始，按本文的第一版范围实现。**

## 1. 这一版搬什么

把旧 SealDice 系统里相互依赖的四块搬进独立 QQ 官方机器人：

- **属性**：保留现有 `role_attrs`，新增属性定义（名称、上下限、默认值、说明）；骰子和 RPG 共用同一份角色属性。
- **物品**：物品库、角色背包、次数/耐用状态、使用后属性变化、管理员调整背包、玩家赠送。
- **商城**：管理员把物品上架，用“货币类物品”定价；玩家查看、购买，扣款与入包在同一数据库事务中完成。
- **地点**：公共/上锁地点、地点钥匙、私人房间开关；私约、官约、心愿统一调用同一个地点校验。

本版不搬：抽取池、保底、合成、二手市场、玩家间交易单、装备/战斗、窃听器等特殊道具。这些后续都能建在本版的物品与背包表上。

## 2. 归属和多机器人隔离

四个模块都是某个机器人的游戏数据，表只写在 `core/db.py` 的 `SCHEMA`，所有读写只走 `get_conn()`。不保存 AppID 列，也不自己拼 `data/bots/<AppID>` 路径；`use_bot()` 选中的工作区就是天然边界。

本功能作为随安装包提供的官方扩展 `rpg`：关闭时不加载 QQ 玩法指令，数据保留；后台管理入口随扩展开关显示。现有“跑团骰子”仍可单独使用 `role_attrs`。

## 3. 数据模型

- `rpg_attr_defs`：属性定义。删除定义不删角色已有数值，避免误丢数据。
- `rpg_items`：物品码唯一；类型先支持 `item` / `currency`；属性效果保存为 JSON，但由核心函数解析和校验。
- `rpg_inventory`：引用 `role_id` 和物品码，保存数量、剩余使用次数与过期时间。
- `rpg_shop`：一个物品一条当前上架记录，价格为正整数，货币必须指向 `currency` 物品。
- `rpg_places`：地点名唯一，带描述和上锁状态。
- `rpg_place_keys`：`(role_id, place_id)` 唯一，删地点/角色时自动清理。
- `rpg_item_log`：记录购买、调整、赠送、使用，便于管理员查问和之后排查经济异常。

新表都用 `CREATE TABLE IF NOT EXISTS`，本次不需要对既有表 `ALTER TABLE`。季度收尾时清空角色会通过外键级联清理背包、钥匙和角色属性；物品库、商城、地点和属性定义保留到下季。

## 4. 共用规则

- `core/rpg.py` 是唯一规则层；QQ 指令和后台都只调它，不各写一份扣款/改属性逻辑。
- 购买、赠送、使用都在一个 SQLite 事务里完成，失败时不留“扣了钱没给物品”的半状态。
- 属性效果受属性定义的上下限约束；未定义的属性仍允许跑团骰子记录，但物品不能引用未定义属性。
- 地点系统关闭时宽松放行，开启后只认存在且可进入的公共地点，或开启的“某某的房间”。
- 指令优先级 10、`block=True`；长列表走现有 `reply_long()`。

## 5. 第一版交互

QQ 玩家：

- `背包 [详情 物品名/码]`
- `商城`、`购买 物品名/码 [数量]`
- `使用 物品名/码 [数量]`
- `赠送道具 角色名 物品名/码 [数量]`
- `地点 查看`、`地点 钥匙`
- 现有 `/录属性`、`/属性`继续有效，并自动采用属性定义的上下限。

后台“物品与地点”页：

- 属性定义的新建/修改/删除；按角色调整属性。
- 物品库新建/修改/删除；按角色增减背包。
- 商城上架/下架。
- 地点新建/修改/删除/上锁；按角色发放或收回钥匙。
