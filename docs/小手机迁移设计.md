# 小手机迁移设计（rp_archive → 长日bot）

目标：每个安装长日bot的人，装好就带着自己的一部小手机，玩家用激活码上网页玩；你现在线上的小手机功能搬过来，但**搬的是功能，不是代码原样**。

## 1. 现状（量过的）

- 代码在 `rp_archive/app.py`，约 1.9 万行；其中小手机相关：153 条 `/p…` 路由、约 200 个手机相关函数。
- 页面：`templates/phone.html` 一个 3251 行的模板靠 `mode` 变量分出全部页面，另有约 30 个 `_phone_*.html` 片段，合计 600KB+。
- 数据：约 45 张 `phone_*` 表，全部按 `tenant_id` + `show_id`（多租户、多季）存。
- 它是 SealDice 插件的**客户端**：插件每 30 秒上报快照（规则、名单、次数、时间线…），网页发的短信、礼物、点歌、心愿等先写进「暂存表」，再等插件下一次同步取走执行、回报 done。

## 2. 三个关键判断（这决定了怎么搬）

1. **同步层整个拿掉。** 新机器人里网页和机器人是同一个进程、同一个 SQLite。网页直接读写核心表（roles、messages、rooms、wishes…），不再有快照、暂存表、`*_done` 游标。约 45 张表里大概 15 张（`phone_sync`、`phone_reports`、各种 `*_ops`）直接消失，逻辑也比现在简单、实时。
2. **去掉多租户。** 一个安装 = 一个团 = 一个季。`tenant_id`、`show_id` 全部去掉，路由里的 `sid` 也去掉。
3. **能力不重写，规则复用核心。** 新机器人已经有短信/礼物/房间/时间线/待回/心愿/关系线/心动信/论坛的规则代码，网页只是它们的另一个入口。网页发短信 = 调 `messaging.queue_message`，和 QQ 里发走同一套限额、拉黑、署名规则，**不再各写一份**。

## 3. 功能盘点：哪些搬、搬成什么

**A. 地基（必搬，第一期）**
激活码登录（独立 cookie、30 天）、首页入口、六套外观 + 六套用语、底栏（消息/发现/+/角色/我的）、违禁词/暂停通讯/档期三道闸、微信名/备注/头像、no-store + noindex + csrf、管理员手机入口。

**B. 核心玩法的网页端（第二期，对应已有核心）**
- 消息：收件箱、对话页、发短信、送礼、礼品店、拉黑
- 时间线、我的待回、我的数量
- 约会：发起私约/电话/微信、加入申请、**网页聊天室（旧的 `phone_rooms`）**——它正好是「群池用完」时的兜底，不用另做
- 心愿、关系线、心动信箱、论坛（旧手机的「公开播报」对应）

**C. 可选玩法（做成官方扩展，默认关，第三期）**
朋友圈、漂流瓶、点歌台、小游戏与排行榜、图书馆。

**D. 重功能（第四期，各自单独评估）**
匿名舞会（`_phone_masquerade.html` 660 行 + 后台）、抽卡、商店与偷窃、前置电话（滑卡配对，319 行）、PWA 推送、语擦日历联动、分享链接。

**E. 不搬 / 以后再说**
- 归档复盘（`/p/me/archive`、`_phone_archive.html`）：依赖存档站对每场对话的记录，新机器人**不存房间聊天内容**。除非你要做存档，否则不搬。
- 字数/弧长统计（`stats`）：同上，数据源没了。
- RPG 背包/属性快照：长日RPG 还不在新机器人里，等做了再接。

## 4. 架构

```
长日bot 进程
├─ 设置平台（127.0.0.1，管理员用，已有）
├─ 小手机（公网端口，玩家用，新）  ← 同一个进程、同一个 SQLite
└─ 机器人（QQ 连接）
```

- 小手机是**第二个 Flask 应用**（蓝图 `phone`），和设置平台分开监听：设置平台只开本机（127.0.0.1），小手机监听公网端口（默认 5092）。**怎么让玩家连上，见下面第 4.1 节，原则是装的人一个字都不用敲。**
- 激活码：玩家在个人群里发「手机码」，机器人回一条链接 + 码；管理员也可在设置平台批量生成/重发。
- 模板：先**原样搬进来跑通**（保证外观和你现在一样），再把 `phone.html` 按页面拆开，每个 mode 一个文件，共用 `_phone_kit` / `_phone_skin` 这些片段。拆分不和功能迁移混在同一步。
- 外观 CSS、六套主题、图标字体照搬；**UI 重做另说**（你之前约定的 UI 稿交 GPT，不在迁移里改）。

### 4.1 公网访问：自动配置（给没有电脑经验的人）

能自动的我们全自动，剩下**必须人点的只有一步**，而且把这一步说成大白话、带截图、点一下就能检查对不对。

**第 1 档：IP + 端口（默认，零门槛）**
`http://服务器IP:5092`，不需要域名，不需要备案。程序自己做：
1. 自动探测服务器公网 IP（已有 `botconf.public_ip`）；
2. 自动放行系统防火墙（Linux 的 ufw/firewalld、Windows 防火墙；安装脚本本来就有管理员权限）；
3. 小手机自动开始监听，并把这个网址写进设置 `phone_base_url`；
4. 机器人发给玩家的「手机码」消息里自动带上完整链接，装的人不用转发网址。

**必须人点的一步**：云服务商（腾讯云/阿里云/华为云…）的「安全组」要放行 5092 端口——这是云厂商控制台里的设置，程序碰不到（除非要用户把云账号的密钥交给程序，风险太大，不做）。我们做的是：
- 设置平台「小手机」页里有一个**「检查玩家能不能打开」按钮**；
- 点它，程序请主页服务器（system.changri.work）反向连一下这个 IP:端口，**几秒内告诉你通了没有**；
- 没通就按你用的云服务商弹出对应的图文步骤（「腾讯云：控制台 → 云服务器 → 安全组 → 添加规则 → 端口 5092」），改完再点检查，直到变绿。

**第 2 档：HTTPS 域名（可选，想要锁头和推送通知的人）**
装的人只做两件事：买/准备一个域名、把它解析到服务器 IP。然后在设置平台填域名、点「开通」，程序自动：
1. 检查域名确实解析到本机 IP，没有就告诉他怎么改；
2. 下载官方 Caddy（固定版本、校验哈希），生成配置、启动、自动申请并续期证书；
3. 放行 80/443，把 `phone_base_url` 改成 https 地址。
注意：**大陆服务器用域名走 80/443 必须先备案**，页面会先问「你的服务器在大陆还是海外」，大陆的说清楚要备案、没备案就继续用第 1 档。

**不做**：不替用户配云账号、不内置第三方隧道（国内不稳、链接会变）、不用 changri.work 给别人发子域名（备案和内容责任都在你名下）。

**第 1 档的安全底线**（因为是明文 HTTP）：激活码要足够长、登录限速防暴力猜；页面上没有任何密码；顶部不吓人但有一行「当前是 http 连接，想要更安全可以开通 HTTPS」。

**整体的「网络体检」页**：一页四个灯——机器人连上了吗 / 小手机在监听吗 / 玩家能从外网打开吗 / 有没有 HTTPS——全绿才算装好。它同样适合第一次安装向导的最后一步。

## 5. 扩展机制要升级（API v2）

可选玩法做成扩展后，需要往小手机里「挂东西」，changri_api 增加：

- `register_phone_page(path, handler, title, icon, group)`：扩展自己带页面，出现在发现页的某个分组
- `register_phone_search(fn)`：让扩展的功能能被小手机搜索找到
- 扩展自己的表建在 `ext_<id>_*` 前缀下，小手机收尾时一并清理
- manifest 里 `api: 2`；v1 扩展照常工作，不受影响

## 6. 数据迁移

- **不导入线上旧数据。** 新装的实例从空开始；你自己的团继续用旧的 rp_archive 小手机，**这次是复制，不是搬走**，旧的不下线。
- 只迁**设置默认值**（外观、用语、违禁词表），不迁玩家数据。
- 收尾（清空本季）要覆盖所有 `phone_*` 新表，**永久保留**的只有小游戏排行榜（旧规则保留）。

## 7. 分期与验收

| 期 | 内容 | 验收 |
|---|---|---|
| P0 | 地基：登录、外观、底栏、发现页空壳、三道闸、手机码指令 | 用激活码登进去，换六套外观，浅/深色都正常 |
| P1 | 消息、礼品店、时间线、待回、心愿、关系线、心动信箱、论坛 | 网页发的短信和 QQ 发的短信同限额、同拉黑；网页与 QQ 数据实时一致 |
| P2 | 约会 + 网页聊天室；管理员手机基础（以玩家身份操作、暂停通讯、违禁词） | 群池用完时房间自动转网页聊天室，双方都能聊、能结束 |
| P3 | API v2 + 扩展：朋友圈、漂流瓶、点歌、小游戏、图书馆 | 每个扩展可单独开关，关掉后入口和路由一起消失 |
| P4 | 舞会、抽卡、商店、前置电话、推送、语擦联动 | 逐个评估，值得再做 |

每期做完：自动测试 + 本机浏览器看 375 宽度浅深色 + 部署贾维斯一个测试实例，你实测后再进下一期。

## 8. 需要你定的事

1. **公网访问**：按第 4.1 节的三档做（默认 IP+端口，一键检查，可选 HTTPS）。需要你在主页服务器上加一个「反向探测端口」的小接口。
2. **归档复盘**：确认不搬（新机器人不存聊天内容）？
3. **你自己的团**：旧 rp_archive 小手机继续用，新旧并行，同意吗？
4. **P0 起步**：先把现有 `phone.html` 原样搬、再拆，还是直接按页面重写模板？前者稳，后者更干净但慢。我倾向前者。
5. **UI**：迁移期间界面保持现状，之后的新样式再交 GPT 出稿，这样可以吗？
