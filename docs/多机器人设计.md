# 多机器人设计（一个机器人 = 一套系统）

状态：**设计稿，等 Erin 确认后才实现。**

## 1. 要解决什么

现在一个安装只有一套数据：一个 `changri.db`，里面的角色、群、季度、设置都不分机器人，`bot_accounts` 只是「能连哪几个机器人」的清单。Erin 的要求：

1. 一个机器人就是一套完整的系统，各管各的角色、季度、设置，互不串。
2. 后台只有一个端口 **5091**。登录后第一屏是**选机器人**，机器人的 AppID/密钥等配置在这个机器人自己的区域里做。
3. 能在不同机器人之间切换。
4. 每个机器人的小手机各用各的端口：5092、5093、5094……

## 2. 核心做法：每个机器人一个独立数据库

```
data/
  changri.db            ← 全局库（账号、机器人清单、更新、远程访问、端口分配）
  bots/
    1906396563/
      changri.db        ← 这个机器人的全部游戏数据和设置
    <另一个AppID>/
      changri.db
```

为什么不是「所有表加一列 bot_id」：现有约 25 张表、几百处 SQL 要全改，漏一处就串数据；独立文件则天然隔离，导出、备份、删除一个机器人也只是一个文件夹。

### 2.1 哪些归全局，哪些归机器人

| 归属 | 内容 |
|---|---|
| **全局库** | `web_users`（后台登录账号）、`bot_accounts`（AppID/密钥/启用/备注）、全局配置（更新通道与版本、远程访问开关与白名单、首次设置码、登录锁定记录）、`bot_ports`（每个机器人的小手机端口分配，见 §6） |
| **机器人库** | `config`（所有游戏设置：开放时段、信箱上限、公开播报、手机外观/用语……）、`roles`、`role_groups`、`bind_codes`、`messages`、`blocks`、`lovemails`、`relations`、`rel_details`、`admins`（QQ 管理员）、`role_attrs`、`seasons`、`entrance*`、`admin_codes`、`pool_groups`、`rooms`、`room_members`、`phone_codes`、`phone_seen`、`join_requests`、`wishes`、`posts`、`replies`、`votes`，以及官方/用户扩展建的表 |

`config` 要拆成两份：键名以 `remote_`、`update_`、`setup_` 开头及少数明确列出的键走全局，其余走机器人。拆分清单写成一个常量 `GLOBAL_CONFIG_KEYS`，防止新增键时放错地方。

扩展：开关状态（启用哪些扩展）**按机器人**存，扩展代码和文件夹是全局共用的；同一个扩展在不同机器人里有各自的设置和数据。

## 3. 怎么让代码知道「现在是哪个机器人」

现有代码几乎都通过 `core/db.py` 的 `get_conn()` / `get_config()` 取数据。**只改这一处**：

- 新增一个 `contextvars.ContextVar`：`current_bot`（AppID 字符串）。
- `get_conn()` 读它：有值就连 `data/bots/<AppID>/changri.db`，没有值就连全局库；`get_config/set_config` 同理，按键名决定走全局还是机器人库。
- 新增 `with use_bot(app_id):` 上下文管理器和 `bot_scope(app_id)` 装饰器。
- 全局库的访问用显式的 `get_global_conn()`，只有账号、机器人清单、更新、远程访问这几处调用它，一眼能看出哪些是全局的。

谁来设置上下文：

| 场景 | 设置方式 |
|---|---|
| QQ 消息进来（指令、绑定、「手机码」等） | NoneBot 事件预处理器：`event` 所属的 `bot.self_id` → `use_bot` |
| 定时任务（季度提醒、窗口、清理……） | 每个定时任务改成「对每个启用的机器人各跑一次」，包一层 `for_each_bot` |
| 后台页面 | 路由 `/b/<AppID>/...`，请求进来时设置；全局页面（账号、更新、远程访问、选机器人）不设置 |
| 小手机 | 每个机器人一个监听端口，该端口的请求线程固定设置自己的 AppID |
| 扩展里的指令 | 走第一行，天然带上下文，`changri_api` 不用改 |

线程说明：contextvar 在 asyncio 任务里自然隔离；Flask 在线程里跑，请求开始时 `use_bot`，结束时复位。`loopbridge` 把协程丢回主事件循环时要显式带上 AppID（复制当前上下文）。

## 4. 后台界面

```
登录
  └─ 选机器人（首页，全局）
       ├─ 卡片：昵称/AppID、在线状态、角色数、当前季度、小手机端口与状态
       ├─ 「添加机器人」：填 AppID + 密钥 + 备注 → 创建工作区 → 自动进入
       └─ 全局入口：后台账号、系统更新、远程访问
  └─ 进入某个机器人 /b/<AppID>/
       ├─ 顶部：当前机器人名 + 切换下拉
       └─ 侧栏：概览、角色、季度、群、功能与设置、小手机、扩展……（现有页面原样）
            └─ 「机器人设置」：AppID/密钥改动、启用/停用、IP 白名单自检、删除工作区
```

- 只有一个机器人时，登录后**自动直接进入它**（卡片页仍可从顶部切换进入），老用户体感几乎不变。
- 密钥只有 owner 账号能看和改，沿用现在的规则。
- 远程访问的 `BLOCKED` 路径要跟着改：`/bots`、「机器人设置」、`/accounts`、`/update`、`/remote` 对远程管理员继续 403。
- 旧地址 `/phone`、`/roles` 等不带机器人的路径：有当前机器人（会话里记着上次选的）就 302 到对应 `/b/<id>/…`，没有就回选机器人页，书签不会断。

## 5. 数据迁移（贾维斯与所有现有安装）

升级后第一次启动：

1. 发现旧单库 `data/changri.db` 且没有 `data/bots/`，进入迁移。
2. 先复制备份为 `data/changri.db.premulti`（不删）。
3. 在 `bot_accounts` 里找机器人：只有一个就把整个旧库**复制**为 `data/bots/<AppID>/changri.db`；有多个（极少见）则让第一个启用的拿走数据，其余建空工作区。
4. 全局库保留 `web_users`、`bot_accounts`、全局配置；机器人库里同样保留一份 `config`，但全局键以全局库为准。
5. 迁移是幂等的：已存在 `data/bots/<AppID>` 就跳过；失败就回退到旧库继续运行并在后台首页提示。

## 6. 小手机端口

- 每个机器人独立开关：`phone_enabled`、`phone_port`、`phone_base_url` 都在机器人库里（现在的配置键不变，只是跟着工作区走）。
- 全局库的 `bot_ports(app_id, port)` 记录谁占了哪个端口，**保存时校验不重复**，并和后台端口（5091）、远程管理端口冲突检查。
- 「开启小手机」向导里建议端口：从 5092 起找第一个「没被别的机器人占、本机也没被别的程序占」的端口，Erin 想用别的可以自己改。
- 启动时 `phoneserver` 为每个已开启的机器人各起一个 uvicorn 线程，线程固定在它的工作区；开关/改端口只重启这一个。
- 防火墙放行：开启或改端口时只放行这个端口（沿用现有的放行逻辑）。
- 探测服务、网络体检页：按「当前进入的机器人」的端口检测，不用改探测服务本身。
- **远程管理端口默认值 5093 要改**（会和第二个机器人的小手机撞）。后台本来就在 5091，远程管理现在是第二个监听口；新方案里它改成「5091 本身带白名单」，不再单独占端口，迁移时旧的 `remote_admin_port` 设置忽略。（待你确认，见 §9。）

## 7. 对其他部分的影响

- **机器人连接**：`bot.py` 现在按 `bot_accounts` 起所有 NoneBot 适配器连接，这个不变；变的只是消息进来后选工作区。
- **QQ 管理员**（`admins` 表）：本来就带 `bot_id` 列，进了机器人库后这列保留但不再起过滤作用，不用改。
- **扩展 API**：`changri_api` 不变，扩展不需要改动；API 里 `all_roles`、`season_name` 等自动取当前机器人。文档里补一句「扩展的数据是按机器人分开的」。
- **更新包**：全局，一次更新所有机器人；各工作区的表结构升级在「第一次被使用」或启动时逐个 `init_db` 执行。
- **安装脚本 / 首次向导**：第一次安装向导里「填 AppID 和密钥」不变，完成后直接创建第一个工作区。
- **测试**：现有测试用 `CHANGRI_DB_PATH` 指向一个临时库。保留这个行为：没有设置多机器人时，`current_bot` 为空且设了该变量，就仍当作单库。新增测试覆盖：两个工作区的数据隔离、上下文切换、迁移幂等、端口冲突、选机器人页与切换。

## 8. 分三步实现，每步都能单独验证和部署

**第 1 步：数据隔离与迁移（地基，不改界面）**
`core/db.py` 的上下文机制、全局库/机器人库拆分、事件预处理器、定时任务逐机器人运行、迁移与备份、测试。完成后单机器人行为和现在一模一样，已有测试全过。

**第 2 步：选机器人页与切换**
`/b/<AppID>/` 路由前缀、选机器人首页、顶部切换、机器人设置页（AppID/密钥/启用/IP 自检）、「添加机器人」、旧路径重定向、全局页面（账号/更新/远程访问）归位。

**第 3 步：小手机按机器人分端口**
`bot_ports`、端口校验与建议、每机器人一个监听线程、向导和网络体检按当前机器人、远程管理端口调整、防火墙逻辑。

每步：本地全量测试 + 浏览器实看 + 备份后部署贾维斯，你实测通过再进下一步。

## 9. 需要你确认的几件事

1. **整体方案**：每个机器人一个独立数据库（§2），同意吗？
2. **只有一个机器人时**：登录后直接进入它（跳过选机器人页），多个时才先选。可以吗？
3. **远程管理端口**：不再单独占 5093，改成「5091 自带白名单」。可以吗？（不同意的话，需要你给它另选一个固定端口，不能落在 5092 往后的小手机段里。）
4. **同一个扩展**：代码全局共用、开关和数据按机器人分开，这样可以吗？
5. **删除机器人**：只允许「停用」，需要真删数据时由你在服务器上手动删文件夹？（我倾向这样，防误删。）
